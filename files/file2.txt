## A-4: ベンチ計測基盤(memset 天井 + GB/s/天井比表示 + xoroshiro 追加)

変更: examples/test.rs に NT ストア並列 memset ベースライン、GB/s・天井比% 表示、
xoroshiro64ss(x8/x16)・xoroshiro128pp/ss をベンチに追加。ライブラリ側は無変更。

**NT-store write ceiling: 26.5 / 27.2 / 27.1 GB/s**(3 回、±1.3%)

### 決定的な事実

純粋な NT memset でも 27.2 GB/s が上限 → **このマシンの 32bit 7.0 GS/s(28 GB/s)は
DRAM 直書きでは物理的に到達不能**(計算ゼロの memset ですら 6.8 GS/s 相当)。
GMI 書き込み帯域仮説が実証された。上位 RNG は既に天井の 98–103% で飽和:

| algo | run1 | run2 | run3 | 天井比 |
|---|---|---|---|---|
| philox32x4x4 | 6.72 | 6.67 | 6.85 | 98–101% |
| xoshiro128ppx16 | 6.84 | 6.80 | 6.77 | 100–103% |
| xoroshiro64ssx16 (新規掲載) | 6.75 | 6.77 | 6.46 | 95–102% |
| xoroshiro64ssx8 (新規掲載) | 6.56 | 6.74 | 6.72 | 99% |
| cet64x8 | 3.29 | 3.42 | 3.36 | 99–101% |
| biski64x8 | 3.37 | 3.43 | 3.33 | 98–102% |

### 伸びしろ(天井未達 = A-1 の対象)

| algo | 現状 | 天井比 | 期待 |
|---|---|---|---|
| threefry32x4 | 5.27–5.82 | 78–86% | NT 化で ~6.7 |
| xoroshiro64ss (scalar) | 5.90–6.00 | 87–91% | NT 化で ~6.5 |
| philox64 | 2.68–2.85 | 79–86% | NT+AVX-512 化で ~3.3 |
| xoroshiro128pp/ss | 2.76–3.06 | 81–90% | 同上 |
| splitmix64 | 2.80–2.98 | 82–88% | 同上 |
| cet256x2 | 2.32–2.50 | 68–75% | 回帰調査 |

→ **目標の再解釈**: 7 / 3.5 GS/s は「天井比 ~100%」と等価(このマシンでは 6.8 / 3.4)。
絶対値で 7 / 3.5 / 10+ を出すには C-1(L3 常駐)が必須。

## A-1: NT ストア徹底

変更:
- `_internal.rs` に `fill_chunk_nt`(AVX2 NT ストア + 末尾 sfence、非アライン時はキャッシュストアにフォールバック)と
  `fill_chunk_auto`(実行時 AVX2 検出ディスパッチ)を追加。
- 書き換え: cabi64/philox, cabi64/xoroshiro, cabi64/splitmix, cabi32/threefry, cabi32/xoroshiro(scalar 64ss)。
  各 RNG×4 メソッドのループを generic フィルヘルパー + 変換クロージャに集約(コードも大幅削減)。
- PAR_CHUNK 4096(16KB)→ 0x20000(512KB)に統一。

教訓(1 回目の実装で threefry が 5.4→2.0 に退行): 旧コードは LLVM が独立カウンタブロックの
20 ラウンド暗号を**ブロック間で自動ベクトル化**していた。バッチ 4 ブロックの閉包構造が
これを阻害 → バッチを 16/32 ブロック(64 出力)の固定トリップカウントループに変更して回復+改善。

結果(3 回、GS/s):

| algo | before (中央値) | after run1/2/3 | 天井比 |
|---|---|---|---|
| philox64 | 2.75 | 3.19 / 3.15 / 3.21 | **94–96%** (+16%) |
| splitmix64 | 2.83 | 3.36 / 3.37 / 3.35 | **99–101%** (+19%) |
| xoroshiro128pp | 2.85 | 3.37 / 3.30 / 3.36 | **98–101%** (+17%) |
| xoroshiro128ss | 2.83 | 3.35 / 3.35 / 3.40 | **99–102%** (+19%) |
| xoroshiro64ss | 5.94 | 6.46 / 6.68 / 6.52 | **95–99%** (+9%) |
| threefry32x4 | 5.45 | 5.87 / 6.26 / 5.82 | 86–93% (+10%) |
| threefry32x2 | 4.59 | 5.21 / 5.26 / 5.08 | 76–78% (+13%) |

64bit 帯域未達組は全て天井比 ~100% に到達。**64bit 実測 3.35–3.40 GS/s = このマシンの物理上限**。
threefry はまだ計算律速(B 項で追加余地)。テスト 63 件全 pass。

## C-1: サイズ適応ストア + L3 常駐モード → **10 GS/s 目標を大幅超過**

変更:
- `_internal.rs`: `NT_THRESHOLD_BYTES = 24MB`、`prefer_nt(_for)`、`fill_chunk_auto(chunk, nt, gen)`。
  バッファ全体が 24MB 以下なら通常(キャッシュ)ストア、超えたら NT ストア。
- stream ハードコードだった cabi32 xoshiro/sfc/xoroshiro/jsf + cabi64 xoshiro/cet/sfc/biski の
  チャンク関数に `nt: bool` を貫通(`aligned` 判定を `nt &&` でゲート)。
- ベンチに L3 常駐モード追加(16MB ワーキングセット × 25 周 = 総生成数は同一)。

**バグと修正**: sfc32x4 のバッチが 16B(u32×4)で `fill_chunk_nt` の 32B 前提に違反 →
release では何もストアされず「29 GS/s」の偽計測 + 出力破損。
(1) バッチを 4 ベクトル束ね(64B)に変更、(2) `fill_chunk_nt` に 32B 未満バッチの
安全フォールバックを追加、(3) `_internal` に充填完全性の回帰テスト 3 件追加(計 66 tests pass)。

結果(3 回、GS/s):

| algo | DRAM モード | **L3 常駐モード** |
|---|---|---|
| jsf32x16 | 6.40–6.60 | **34.7 / 43.8 / 34.7** |
| xoshiro128ppx16 | 6.56–6.69 | **38.3 / 38.2 / 37.4** |
| xoroshiro64ssx16 | 6.56–6.61 | **38.5 / 39.5 / 38.1** |
| sfc32x8 | 6.25–6.49 | 13.2 / 15.4 / 13.2 |
| biski64x8 | 3.13–3.33 | **29.7 / 28.4 / 39.5** |
| sfc64x8 | 3.23–3.28 | **27.6 / 29.1 / 36.7** |
| cet64x8 | 3.28–3.32 | **27.9 / 38.3 / 29.1** |
| xoshiro256ssx2 | 3.28–3.37 | **26.2 / 27.8 / 29.4** |
| xoroshiro128pp | 3.10–3.33 | 7.4 / 7.5 / 7.6 |
| splitmix64 | 3.10–3.30 | 6.5 / 6.6 / 6.5 |

- **32bit: 34–44 GS/s、64bit: 26–40 GS/s** — L3 (96MB X3D) 内で書き込みが完結し
  GMI/DRAM 制約を完全回避。10 GS/s 目標達成(L3 常駐ワークロード時)。
- L3 値の振れ幅(±20%)はキャッシュ常駐ベンチの特性(eviction タイミング・クロック変動)。
- 未変換組(philox32/squares/pcg/splitmix32 系は stream 構造が独自)は L3 モードでも ~5–6 で
  頭打ち → B 項の対象。philox64/threefry は計算律速。
- この回の計測では計算律速組(threefry, mt 等)が全体に ~10% 低め — 長時間ベンチ後の
  クロック/温度変動によるもので、帯域律速組は天井比 ~100% を維持。

## B: 下位アルゴリズムの底上げ(単一スレッド組の並列化)

変更:
- `_internal.rs` に `par_fill_reseed32` / `par_fill_reseed64`(チャンクごと再シード +
  サイズ適応ストア + 64B バッチ)を追加。
- 変換: pcg32, splitmix32, sfc32, xoshiro128pp/ss, jsf32(4KB チャンク撤廃),
  mt19937, sfmt19937, **SFMT 全 9 変種(マクロ本体 1 編集)**, mt1993764, sfmt1993764。
- `fill_next_u32s/u64s`(逐次ブロック充填)は将来用に `#[allow(dead_code)]` で保持。
- 注意: これらの fill 系 API は「単一ストリーム逐次」から「チャンク並列・チャンクごと再シード」に
  意味が変わる(クレートの既存パターンと同方式)。

結果(3 回、GS/s):

| algo | before | after | 倍率 |
|---|---|---|---|
| pcg32 | 0.91–0.92 | 6.54–6.70 | **×7.2** |
| splitmix32 | 1.15–1.26 | 6.59–6.82 | ×5.6 |
| sfc32 | 1.13–1.26 | 6.50–6.60 | ×5.4 |
| xoshiro128pp | 1.19–1.29 | 6.32–6.69 | ×5.3 |
| mt19937 | 2.54–3.00 | 6.31–6.64 | ×2.3 |
| sfmt19937 | 1.74–1.99 | 6.52–6.65 | ×3.5 |
| sfmt607–216091 | 1.5–3.2 | 6.4–6.8 | ×2–4 |
| jsf32 | 5.4–6.1 | 6.73–6.78 | ×1.15 |
| mt1993764 | 1.21–1.40 | 3.29–3.34 | **×2.5** |
| sfmt1993764 | 0.88–0.96 | 3.28–3.35 | ×3.6 |

全変換対象が天井比 93–101% に到達。**ベンチ掲載の全アルゴリズム中、天井未達は
計算律速の threefry(~78–93%)・philox64(~94%)・philox32x4(構造が x4x4 と重複、非推奨候補)・
threefish256(72 ラウンド暗号、0.08)のみ**。

### 見送り(理由付き)

- **threefish256 (0.08)**: counter-mode 並列化は可能だが 72 ラウンド Threefish の計算律速は
  解消されず、効果は ×16 でも 1.3 GS/s 止まり。暗号用途 PRNG であり優先度低。
- **philox32x4 (2.2)**: AVX-512 版 philox32x4x4 と役割重複。非推奨化を推奨。
- **cet256x2 (2.1–2.5, 63–75%)**: cet64x8 と比べたチャンクパスの監査は未実施(TODO)。
- **lcg / xorshift / twisted_gfsr**: ベンチ未掲載のため未変換(同じ `par_fill_reseed*` で変換可能)。

## C-2: 生成と消費の融合 API(設計メモ、コード変更なし)

L3 常駐でも「書く→読む」の 2 パスはキャッシュ帯域を二度払いする。
究極の生成スループットは消費側をクロージャで受ける API:
`Rng32V512::nextuv()` を直接ループで呼び reduce する(モンテカルロ等)。
C ABI には載らないため Rust API として docs に例を載せる程度に留める(将来課題)。

## 総括

| 指標 | Baseline | 最終 | 目標 |
|---|---|---|---|
| 32bit 最速 (DRAM 400MB) | 6.8 GS/s | 6.8 GS/s (= memset 天井) | 7.0 → **物理上限により未達**(天井比 100% は達成) |
| 64bit 最速 (DRAM 800MB) | 3.4 GS/s | 3.4 GS/s (= memset 天井) | 3.5 → 同上 |
| 32bit 最速 (L3 常駐 16MB) | — | **34–44 GS/s** (jsf32x16) | 10 → **大幅達成** |
| 64bit 最速 (L3 常駐 16MB) | — | **26–40 GS/s** (biski64x8) | 3.5 → 大幅達成 |
| ベンチ最下位層 | 0.9–1.3 GS/s ×8 本 | 全て天井比 93%+ | — |

9800X3D の DRAM 直書き 7 GS/s は **NT memset ですら 6.8 が上限**のため物理的に不可能
(単一 CCD の GMI 書き込み帯域)。i5-12450H(モノリシック)では同じコードがより高い
DRAM 天井まで出るはず — 「天井比」での比較を推奨。L3 に収まるワーキングセットでは
本変更(サイズ適応ストア)により 30–40 GS/s 級が出る。
